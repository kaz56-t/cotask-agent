# 🛠 実装TODOリスト：Multi-Agent Orchestrator (テスト項目付き)

## Phase 1: 基盤セットアップ（1コマンド起動の準備）

**タスク:** docker-compose.yml, 各 Dockerfile, .env の作成。

**ゴール:** docker-compose up を実行して、3つのコンテナ（Frontend, Backend, Runtime）がエラーなく立ち上がること。

### 人間のテスト事項:

- [x] http://localhost:3000 にアクセスしてNext.jsの画面（空でも可）が表示されるか？
- [x] http://localhost:8000/docs（Swagger UI）にアクセスできるか？
- [x] ターミナルで docker ps を叩き、3つのコンテナが Up 状態になっているか？

## Phase 2: バックエンド & AutoGenの構築

**タスク:** AutoGenエージェント定義、SQLite接続、並列数制御ロジックの実装。

**ゴール:** Pythonスクリプト経由でAutoGenが起動し、指定した別コンテナでコードが実行されること。

### 人間のテスト事項:

- [ ] 環境構築: pipではなく、uvでパッケージをインストールしているか？
- [ ] エージェント分離テスト: AutoGenが生成したコードが「backendコンテナ内」ではなく「runtimeコンテナ」で実行されているか？（ファイル生成場所などで確認）
- [ ] 並列制限テスト: 4つのタスクを同時に投げた際、3つが実行中になり、1つが「待機(Pending)」になるか？

## Phase 3: API & 通信の実装

**タスク:** ログ送信用WebSocketの実装、成果物(Artifacts)配信設定。

**ゴール:** バックエンドで動いているAutoGenの生のログが、リアルタイムにフロントエンド（またはクライアント）へ届くこと。

### 人間のテスト事項:

- [ ] ログのリアルタイム性: エージェントが考えている最中のテキストが、逐次ターミナルやPostman等に流れてくるか？
- [ ] 成果物アクセス: data/artifacts/test.txt を手動で置き、ブラウザからURL叩いてダウンロードできるか？

## Phase 4: フロントエンド（Next.js）の実装

**タスク:** ダッシュボードUI、タスク作成フォーム、並列数設定画面。

**ゴール:** ブラウザ上の操作だけで、タスク作成から完了、成果物ダウンロードまで完結すること。

### 人間のテスト事項:

- [ ] マルチタスク表示: 左側のサイドバーで、実行中の複数のタスクの進捗（％やステータス）が個別に更新されているか？
- [ ] 動的設定変更: UIで並列数を「1」に変更したとき、実行中のタスクが制限されるか？
- [ ] 成果物受け取り: エージェントが作成したファイル（例: result.csv）のリンクが表示され、保存できるか？

## Phase 5: 仕上げとテスト

**タスク:** エラーハンドリング、クリーンアップ、全体最適化。

**ゴール:** 不適切な入力やAPIエラーが発生しても、システムがクラッシュせずにユーザーへ通知されること。

### 人間のテスト事項:

- [ ] 異常系テスト: APIキーを無効にしてタスクを開始した際、適切に「Error」ステータスになるか？
- [ ] コンテナ掃除: タスクを削除した際、Docker上の不要な実行ログや一時的なファイルが削除されているか？
- [ ] 再起動テスト: docker-compose down してから再度 up した際、以前のタスク履歴が消えずに残っているか？
